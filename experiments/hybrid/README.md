# experiments/hybrid — a dispatcher over the ladder, and why it lost

## What was tried

glibc picks a different memcpy routine per size. Almost every rung in this
project is faster than glibc at *some* size, so the obvious move is to do what
glibc does: route each size to whichever of our own rungs measured fastest.

`hybrid.c` is that dispatcher and nothing else. It contains no copy loop of its
own — it classifies `n`, indexes a table, and tail-calls the winning rung.
`routing_table.h` is generated by `scripts/gen_routing_table.sh` from
`min_of_mins` measured in a single window set (9 windows x 5 reps, pinned to one
CPU) across the 13 ladder sizes, per target. Nothing in it was chosen by hand.
`route_check.c` verifies the compiled table: exhaustive class mapping over 0..8
MiB and `SIZE_MAX`, then copies at every class boundary, boundary ±1 and the
sizes in between, against the byte-at-a-time reference with 64 B canaries on
both sides.

## What was measured

17 sizes x 3 targets = 51 cells, each with the sanctioned tier verdict against
glibc:

- **2 wins** — znver3 300 KB +6.20% (Tier A), v3 16 B +10.86% (Tier A, and only
  because the null band at 16 B is 9.5% wide there).
- **22 losses** — the entire 64 B .. 20 KB band on all three targets, mostly not
  marginal: -30% to -75.92% at 64 B..512 B, -22.50% at 1 KiB on v3, -12.57% at
  16/32 B on znver3/v3.
- **27 unresolvable** — Tier B `measured`, including every 1 MiB+ cell. The raw
  deltas there favour the hybrid (+9.30/+8.07/+11.24% at 1 MiB) but Tier B's 25%
  floor is not cleared, so they are not claims.

Against the strongest single rung (`asm`) it does win where that rung is worst —
64 B on all three targets (+42.18%, +25.04%, +42.18%), and its worst case
against the per-size floor is +14.32/+28.69/+14.32% where `asm`'s is
+60.17..+90.27%. That is the one thing the experiment established: **no single
rung wins everywhere**. It is not enough to make the dispatcher a shippable path.

## Why it lost

1. **The lookup costs more than the copy at small sizes.** 2.5 ns for the hybrid
   against 2.2 ns for the rung it calls at 16 B: one table load and an indirect
   jump, on a copy that is 2.2-9.5 ns at 16 B..512 B. It never gets closer than
   6.4% to the per-size floor in that band.
2. **One class routes on noise.** The 16 B class was chosen on a 0.00% margin
   against the null band, at the one size where an error is largest relative to
   the work — and it is a certified LOSS against `asm` on two targets.
3. **The gap to glibc is kernel quality, not routing.** The dispatcher sends 64 B
   to our best small-size rung (3.4 ns) instead of the one it was replacing
   (5.9 ns) — a large win against ourselves — and glibc is still 2.5 ns. Optimal
   routing among our rungs does not remove the deficit, which refutes the
   hypothesis the experiment was built around.
4. **The table is only as stable as one window set.** 5 of 39 cells disagreed
   between the same-window log and the frozen CSVs, and the routing differs per
   target at 64 KiB and 4 MiB. A different campaign would move some cells.

## How to reproduce

```sh
make experiments
./experiments/hybrid/route_check        # exhaustive class mapping + 420 copies, no clocks
./experiments/hybrid/bench_hybrid --list
./experiments/hybrid/bench_hybrid --impl glibc,asm,hybrid --sizes 16,64,4096 \
    --reps 5 --iters 4000                # run under taskset -c 2 for a comparable number
```

The frozen campaign CSVs are in `data/` (`phase2_hybrid_{znver2,znver3,v3}.csv`).
They are the record of the VPS campaign and are not regenerated by the commands
above, which measure this host. `routing_table.h` came from
`scripts/gen/gen_routing_table.sh`, run against that campaign's raw window logs;
the logs stayed on the VPS, so the table ships as frozen data rather than as
something a cloner can re-derive. The generator is included so the derivation can
be read, not re-executed.

## Verdict

**This is a documented loss, not a deliverable.** It is not built by default, it
is not in the public API, and `make gate` does not audit it. It ships so the
negative result can be verified rather than believed.
